# 🌌 About LifeOS

LifeOS is a modular, AI-powered personal productivity platform designed to bring different parts of everyday life into one connected system.

Tasks live in one place.

Projects somewhere else.

Notes, journals, habits, finances, learning, and ideas often end up scattered across different applications.

**LifeOS brings them together.**

The long-term goal is not simply to build another productivity dashboard.

It is to create a **Personal Operating System** where the different parts of your life can work together, while AI helps you understand and manage the information without taking control away from you.

---

# ✨ Vision

LifeOS follows one simple philosophy:

> **Build the system first. Make it intelligent second.**

Every core module should remain useful without AI.

AI exists to:

- Reduce repetitive work
- Search information naturally
- Summarize data
- Identify patterns
- Prioritize information
- Connect information across modules
- Provide useful insights

The user always remains in control.

# 🏗️ Architecture

LifeOS uses a modular application architecture.

```text
LifeOS
│
├── app/
│   ├── ai-assistant/
│   ├── analytics/
│   ├── calendar/
│   ├── finance/
│   ├── habits/
│   ├── idea-vault/
│   ├── journal/
│   ├── learning/
│   ├── media/
│   ├── notes/
│   ├── projects/
│   ├── settings/
│   └── tasks/
│
├── components/
│   ├── dashboard/
│   ├── tasks/
│   ├── projects/
│   ├── journal/
│   ├── habits/
│   ├── finance/
│   ├── notes/
│   └── ...
│
├── hooks/
│   ├── useTasks
│   ├── useProjects
│   ├── useCalendar
│   ├── useNotes
│   ├── useHabits
│   ├── useFinance
│   ├── useLearning
│   ├── useMediaVault
│   └── ...
│
├── lib/
│   ├── Supabase clients
│   ├── utilities
│   └── shared logic
│
├── supabase/
│   └── database migrations
│
└── middleware.ts
```

The general application flow is:

```text
UI
 ↓
Feature Components
 ↓
Custom Hooks
 ↓
Supabase / API
 ↓
PostgreSQL
```

AI functionality is exposed through dedicated server-side API routes.

# 🗄️ Database

LifeOS uses **PostgreSQL through Supabase**.

Database development is organized through incremental SQL migrations covering the application's major modules.

Current database areas include:

- Tasks
- Subtasks
- Projects
- Calendar
- Journal
- Habits
- Habit Logs
- Finance
- Learning
- Media
- Ideas
- AI Outputs
- Reviews
- Settings

Authentication and ownership-based Row Level Security are currently being implemented and hardened.

The target security model is:

```text
Authenticated User
       │
       ▼
   auth.uid()
       │
       ▼
    user_id
       │
       ▼
Only that user's data
```

---

# 🔐 Authentication & Security

Security is currently one of the main development priorities.

LifeOS uses:

- Supabase Authentication
- PostgreSQL Row Level Security
- Server-side Supabase clients
- Protected application routes
- Environment variables for secrets
- User-owned database records

The current development phase is focused on completing authentication and ensuring strict user-level data isolation.

Before a production release, authentication and RLS policies will be thoroughly tested and audited.

# ⚙️ Getting Started

## Prerequisites

Make sure you have:

- Node.js 18+
- npm
- A Supabase project
- An AI provider API key

---

## 1. Clone the repository

```bash
git clone https://github.com/franklingeezer/lifeos.git
cd lifeos
```

---

## 2. Install dependencies

```bash
npm install
```

---

## 3. Configure environment variables

Create:

```text
.env.local
```

Add the environment variables required by the application.

Example:

```env
NEXT_PUBLIC_SUPABASE_URL=your_supabase_project_url
NEXT_PUBLIC_SUPABASE_ANON_KEY=your_supabase_anon_key

AI_API_KEY=your_ai_provider_key
```

> Never commit `.env.local` or private API keys to GitHub.

---

## 4. Configure Supabase

Create a Supabase project and apply the SQL migrations from:

```text
supabase/
```

in the appropriate order.

Authentication and Row Level Security should be configured before using LifeOS with real personal data.

---

## 5. Start the development server

```bash
npm run dev
```

Open:

```text
http://localhost:3000
```
